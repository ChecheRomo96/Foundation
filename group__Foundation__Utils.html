Detailed Description

Program-memory helpers.

Utils provides the program-memory access used by constant tables on AVR. Move and Swap were removed in 2.0.0: use cpstd::move and cpstd::swap from CPSTL.

Program-Memory Data

AVR is a Harvard architecture: an ordinary const table is copied from flash into the small RAM at startup. FOUNDATION_FLASH expands to PROGMEM on AVR and to nothing elsewhere, and Foundation::Utils::Flash reads the data back identically on every target:

const uint16_t Table[] FOUNDATION_FLASH = {100, 250, 400};
const char Name[] FOUNDATION_FLASH = "Foundation";
uint16_t value = Foundation::Utils::Flash::Read(&Table[1]);
char buffer[8];
size_t length = Foundation::Utils::Flash::CopyString(buffer, sizeof(buffer), Name);

Only namespace-scope const objects of trivially copyable types may be placed with FOUNDATION_FLASH, and on AVR they must never be dereferenced directly. Read returns a RAM copy, Copy transfers raw bytes, and CopyString follows snprintf semantics: it always terminates a non-empty buffer and returns the full source length so truncation can be detected. Placement is verified by linking tests/AvrConsumer, whose flash table and string appear in .text rather than .data.

Runnable Example

Foundation_Utils_FlashData reads a table entry and copies a string from program memory. See Examples for build and launch instructions.

◆ FOUNDATION_FLASH

#define FOUNDATION_FLASH

Places a namespace-scope const object in program memory.

On AVR this expands to PROGMEM, so the object stays in flash instead of being copied to RAM at startup. Such an object must only be read through Foundation::Utils::Flash. On every other target, where constant data is already addressable in place, it expands to nothing.

const uint16_t Table[] FOUNDATION_FLASH = {1, 2, 3};
uint16_t second = Foundation::Utils::Flash::Read(&Table[1]);

Copies a string declared with FOUNDATION_FLASH into a buffer.

Follows snprintf semantics: at most capacity - 1 characters are written followed by a terminator, and the full source length is returned so that truncation can be detected. A zero capacity writes nothing.
