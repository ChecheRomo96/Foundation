Detailed Description

Repeatable acceptance matrix for native and cross-compiled targets.

This page defines what “the workflow works” means. A successful compilation alone is not enough for a release artifact. Each supported target must pass the checks that are meaningful for that target class.

Acceptance Criteria

A target passes workflow validation when all applicable items below pass:

  1. CMake accepts the preset and records the intended compiler and processor.
  2. Foundation builds independently in Debug and Release from one build tree.
  3. The local Debug and Release archives are different files with the correct target object format and architecture.
  4. One export operation installs only the Release archive, public headers, package files, and target metadata into dist/<preset>.
  5. FoundationTargets-release.cmake maps consumers to the Release archive, and no Debug archive or Debug import file is present in the package.
  6. A separate Release consumer compiles against the installed headers and links the imported target.
  7. Registered native executable tests pass in Debug and Release. Cross-compiled behavior is validated in real firmware or an appropriate emulator.
  8. Doxygen builds without unresolved workflow references.

Record the host OS and architecture, preset, CMake version, generator, compiler version, exact command, result, and artifact inspection output for every run. This makes a failure reproducible instead of machine-specific.

Test-Suite Scope

The default native configuration builds seven module-scoped GoogleTest executables covering Math, TypeTraits, Utils, Containers, Functional, Time, and Scheduling. CTest discovers their individual cases. A feature override conditionally removes every test target whose required modules are no longer all available. Always inspect the reported case count; --allow-no-tests or -AllowNoTests only validates configuration and compilation when zero tests are present and is not a release-test pass.

Do not run test.sh or test.ps1 as an execution test for STM32 or AVR. Examples are not tests, and cross-compiled binaries cannot run directly on the host. Embedded validation consists of library compilation, archive inspection, consumer/firmware linkage, and target execution where hardware is available.

Common Preflight

Run before platform-specific checks:

cmake --version
cmake --list-presets=all
git status --short

CMake 3.25 or newer is required by the root project. Ninja must be available for every Ninja or Ninja Multi-Config preset. Confirm that the intended compiler resolves before configuring; a different compiler with the same executable name can create an incompatible archive.

STM32 Matrix

Select the preset that matches the firmware CPU and floating-point ABI:

  • stm32f103_armgcc_cortex_m3_soft;
  • stm32f407_armgcc_cortex_m4f_hard;
  • stm32h743_armgcc_cortex_m7f_hard.

The presets build a static library only. Startup code, interrupt vectors, CMSIS, HAL, device definitions, memory layout, linker script, and flashing remain responsibilities of the consuming STM32 firmware project.

arm-none-eabi-gcc --version
arm-none-eabi-g++ --version
arm-none-eabi-g++ -print-sysroot
./scripts/clean.sh stm32f407_armgcc_cortex_m4f_hard --dist
./scripts/configure.sh stm32f407_armgcc_cortex_m4f_hard --fresh
./scripts/build.sh stm32f407_armgcc_cortex_m4f_hard \
--config Debug --target Foundation
./scripts/build.sh stm32f407_armgcc_cortex_m4f_hard \
--config Release --target Foundation
./scripts/export.sh stm32f407_armgcc_cortex_m4f_hard --fresh
arm-none-eabi-objdump -f \
dist/stm32f407_armgcc_cortex_m4f_hard/lib/libFoundation.a
grep -E "Foundation_(PLATFORM|SYSTEM|PROCESSOR|ARM)" \
dist/stm32f407_armgcc_cortex_m4f_hard/lib/cmake/Foundation/FoundationBuildInfo.cmake

Compile and link the exported package in the actual STM32 firmware with the same -mcpu, -mthumb, -mfloat-abi, and -mfpu values. A successful Foundation archive build does not prove that the final firmware uses a compatible runtime or linker configuration. If configuration cannot find stdint.h, install the target Newlib/runtime or pass a compatible FOUNDATION_ARM_SYSROOT during a fresh configure/export.

AVR Matrix

The initial AVR preset is exact: ATmega328P, AVR-GCC, and AVR5. Do not use its archive for another AVR MCU without validating binary compatibility and adding an explicit device profile.

avr-gcc --version
avr-g++ --version
avr-g++ -mmcu=atmega328p -print-file-name=include
./scripts/clean.sh atmega328p_avrgcc_avr5 --dist
./scripts/configure.sh atmega328p_avrgcc_avr5 --fresh
./scripts/build.sh atmega328p_avrgcc_avr5 \
--config Debug --target Foundation
./scripts/build.sh atmega328p_avrgcc_avr5 \
--config Release --target Foundation
./scripts/export.sh atmega328p_avrgcc_avr5 --fresh
avr-objdump -f \
dist/atmega328p_avrgcc_avr5/lib/libFoundation.a
grep -E "Foundation_(PLATFORM|SYSTEM|PROCESSOR|AVR)" \
dist/atmega328p_avrgcc_avr5/lib/cmake/Foundation/FoundationBuildInfo.cmake

The Release archive must contain elf32-avr objects with architecture avr:5. Validate the installed package with a separate CMake consumer that calls a non-inline Foundation function, then inspect the ELF with avr-size and avr-objdump. Hardware execution remains the final check for timing, memory, startup, and board integration.

Package Checks

For every exported target, confirm these files exist:

dist/<preset>/include/
dist/<preset>/lib/<release archive>
dist/<preset>/lib/cmake/Foundation/FoundationConfig.cmake
dist/<preset>/lib/cmake/Foundation/FoundationBuildInfo.cmake
dist/<preset>/lib/cmake/Foundation/FoundationTargets-release.cmake
Foundation
Definition Complex.h:11

Confirm that no Debug archive or FoundationTargets-debug.cmake remains from an older package. Search the Release target file for IMPORTED_LOCATION_RELEASE. A downstream Release CMake project should use find_package(Foundation CONFIG REQUIRED) and Foundation::Foundation; consumers should not hard-code archive names. For native presets, run the repository-owned standalone check after export:

./scripts/test-package.sh <preset> --skip-export

See Package Consumer Validation for the equivalent PowerShell command, exact coverage, and cross-compilation boundary.
