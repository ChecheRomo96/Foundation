Detailed Description

Clock abstractions and time utilities.

Time models a monotonic wrapping counter and the values derived from it. A Clock binds a raw counter callback and a Frequency; Now() combines the current value with the identity of that Clock in a TimePoint. Duration stores a validated elapsed count, while Frequency and Period describe the scale of each tick. FOUNDATION_TIME enables this complete family. TypeTraits is a required module dependency because Tick representations are constrained at compile time.

Tick Representations

Tick<T> is a strongly typed raw counter value. Its representation defaults to uint32_t and must satisfy TypeTraits::is_unsigned_integer<T>; signed integers, floating-point values, classes, and bool are rejected at compile time. The standard aliases are exact specializations:

using Tick8 = Tick<uint8_t>;
using Tick16 = Tick<uint16_t>;
using Tick32 = Tick<uint32_t>;
using Tick64 = Tick<uint64_t>;

Tick<>, Tick<uint32_t>, and Tick32 are the same type. Foundation does not add a separate non-template Tick alias. The short names Duration, TimePoint, and Clock use their Tick32 template defaults; another width is selected through the corresponding generic type:

using TimerClock = Foundation::Time::BasicClock<
Foundation::Time::Tick16
>;
using TimerDuration = Foundation::Time::BasicDuration<
Foundation::Time::Tick16
>;

Modular Time and Validity

  • Every bit pattern is a valid raw Tick. Tick itself does not decide whether two counter samples are chronologically comparable.
  • Duration is valid from zero through one less than the Tick half-range. For Tick32, that is 0..2,147,483,647 ticks. Larger construction values, arithmetic overflow, and subtraction underflow produce an invalid Duration.
  • Duration::IsValid() distinguishes invalid arithmetic from a real zero duration. Conversion methods return zero for an invalid Duration.
  • A default TimePoint has no Clock and IsValid() returns false.
  • Raw counter samples enter the model through Clock::Now() or Clock::At(ticks). TimePoint arithmetic may derive new points while preserving that identity. The raw identity constructor is not public, so callers cannot attach a point to an unrelated Clock.
  • Compatible TimePoints are ordered using modular half-range arithmetic. This correctly handles one counter rollover when the actual separation is less than half the selected Tick range.
  • Subtracting a chronologically earlier compatible point from a later point returns a valid Duration. Reverse subtraction, the exactly-half-range case, invalid points, and different Clock identities return an invalid Duration.
  • Relational operators return false when points have different Clock identities or their order is ambiguous.
  • TimePoint stores a non-owning Clock pointer. Clock is neither copyable nor movable, which keeps its object identity stable; it must still outlive every point, task, and scheduler that references it.
  • Frequency and Period are backed by Math::UnsignedRatio. Both numerator and denominator must be non-zero; zero represents an invalid or unconfigured value rather than a frequency or period with an undefined reciprocal.
  • Every valid Frequency has a valid reciprocal Period and vice versa. Invalid numeric conversions return zero and reciprocal conversions return an invalid value of the opposite type.
  • Duration conversion requires the Period belonging to the relevant Clock.

Compile-Time and Exception Contract

Construction, access, mutation, validation, scalar conversion, and arithmetic on Tick, Frequency, Period, Duration, and TimePoint are constexpr and noexcept where applicable. Reciprocal conversion between Frequency and Period is non-throwing. Clock configuration accessors are also non-throwing, but Clock::Now() intentionally has no noexcept guarantee because it invokes caller-provided code.
