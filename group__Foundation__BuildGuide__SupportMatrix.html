Evidence-based Foundation 1.x support levels for every public target preset.

This page defines the support evidence for the Foundation 1.x release line. Foundation 1.2.0 is the current published release. A preset being present in CMakePresets.json proves that a build identity is described; it does not by itself prove that its compiler, package, consumer, or target execution has been validated.

Support Levels

Level Meaning
PUBLISHED A package for this exact target identity was produced from a version tag and passed native tests plus the standalone package consumer.
RELEASE CANDIDATE Intended to become supported in the 1.x line, but its required validation remains incomplete.
SUPPORTED All applicable release gates passed on the released commit and Foundation commits to maintaining that target for the 1.x line.
EXPERIMENTAL Preset or integration is available for evaluation, but compatibility is best effort.
DEFERRED Explicitly outside the current 1.x scope. No release package or compatibility promise is made.
INTERNAL Repository workflow infrastructure, not a consumer platform or distributed binary identity.

PUBLISHED records verifiable package delivery; it does not grant license rights or claim hardware validation. A RELEASE CANDIDATE or PUBLISHED row becomes SUPPORTED only when its validation task in Foundation 1.x Stabilization Backlog is DONE. If that evidence cannot be completed, the row remains explicitly limited; it must not silently become a broader support claim.

Native Desktop Targets

Native targets must compile and run the non-zero GoogleTest suite in Debug and Release, export a Release-only package, run applicable examples, and link a separate package consumer.

macos_x64 may be cross-built on Apple Silicon, but execution still requires Rosetta or Intel hardware. Linux Arm64 requires a native Arm64 runner or Raspberry Pi-class host; an x86-64 container is not equivalent evidence.

Named Embedded Targets

Embedded support has separate compile/package and execution evidence. A successful archive build is necessary but not sufficient: the exported package must link into firmware built with the same compiler, CPU, ABI, and FPU settings. Representative hardware or an appropriate emulator provides the behavioral evidence.

PSoC remains experimental until its exact product toolchain and a real consumer project are validated. The STM32 presets do not promise CMSIS, HAL, startup files, linker scripts, device macros, or flashing support; those are owned by the consuming firmware.

Source-Mode Integrations

Integration 1.x level Scope
Arduino Uno / ATmega328P source mode RELEASE CANDIDATE The documented sketches must compile with the declared Arduino AVR core.
Other Arduino cores EXPERIMENTAL Source-compatible by design, but not validated as a group. Each architecture needs explicit evidence.
Direct source inclusion in a higher-level CMake project EXPERIMENTAL The supported v1 consumer path is the exported package; source inclusion still requires a dedicated consumer contract.
PIC DEFERRED No current preset, toolchain, package, or compatibility promise.

Workflow-Only Presets

Preset 1.x level Purpose
documentation INTERNAL Builds Doxygen output; it is not a Foundation binary package.

Hidden presets such as base, docs_base, and testing_base are inheritance implementation details and are not user-selectable compatibility targets.

Release Rule

Each release tag freezes its support evidence. A published package may be described as PUBLISHED only when the tagged workflow produced that exact identity. Adding a compiler, architecture, ABI, MCU, or board requires its own validation and a later compatible release; similarity to an existing preset is not proof of support.
