Detailed Description

Generic callback wrapper for free functions and member functions.

Callback provides a lightweight mechanism for storing and invoking callable targets without requiring dynamic memory allocation.

Supported callable types:

  • Free functions.
  • Static member functions.
  • Non-const member functions.
  • Const member functions, including bindings to const objects.

The implementation is intended for embedded and desktop applications where deterministic memory usage is important.

Overview

A Callback object can be in one of three states:

  • Unbound.
  • Bound to a free function.
  • Bound to a member function and object instance.

Invocation is performed through a common interface:

callback.Invoke(...);

Free Functions

Binding a free function:

void OnMessage(uint8_t value) { }
Foundation::Functional::Callback<void, uint8_t> callback;
callback.Bind(OnMessage);
callback.Invoke(42);

Member Functions

Binding a non-static member function:

class Printer {
public:
void Print(uint8_t value) { }
};
Printer printer;
Foundation::Functional::Callback<void, uint8_t> callback;
callback.Bind<Printer, &Printer::Print>(&printer);
callback.Invoke(42);

Return Values

Callbacks may return values:

int Add(int a, int b) {
return a + b;
}
Foundation::Functional::Callback<int, int, int> callback;
callback.Bind(Add);
int result = callback.Invoke(2, 3);

Signature Model

An empty parameter pack represents a callback without arguments. Do not use void as an argument placeholder.

Signature Meaning
Callback<R, Args...> Returns R and receives one or more declared arguments.
Callback<R> Returns R and receives no arguments.
Callback<void, Args...> Returns nothing and receives one or more declared arguments.
Callback<void> Returns nothing and receives no arguments.

The implementation therefore needs only the primary non-void template and one partial specialization for a void return. The empty Args... pack naturally covers both no-argument forms.

Binding State and Lifetime

IsBound() reports whether a target is available and Unbind() clears it. Passing a null free-function or object pointer leaves the callback empty. A member binding never owns its object; the object must outlive the binding and every synchronous Invoke() call.

Embedded Usage

Callback is designed to:

  • Avoid heap allocation.
  • Avoid RTTI.
  • Avoid virtual dispatch.
  • Work on resource-constrained microcontrollers.

Typical applications include:

  • Event systems.
  • State machines.
  • MIDI message handlers.
  • Interrupt dispatchers.
  • Task schedulers.
  • Hardware abstraction layers.

Related Components

Callback is commonly used by:

  • Message parsers.
  • Event dispatchers.
  • Scheduling systems.
  • Driver callbacks.
