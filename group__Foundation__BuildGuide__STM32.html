STM32 Cortex-M3, M4F, and M7F target families.

STM32 support should be separated by family/core/FPU mode.

Supported target presets:

stm32f103_armgcc_cortex_m3_soft
stm32f407_armgcc_cortex_m4f_hard
stm32h743_armgcc_cortex_m7f_hard

These presets map to reusable core/ABI profiles:

Preset CPU Float ABI FPU
stm32f103_armgcc_cortex_m3_soft Cortex-M3 soft none
stm32f407_armgcc_cortex_m4f_hard Cortex-M4 hard fpv4-sp-d16
stm32h743_armgcc_cortex_m7f_hard Cortex-M7 hard fpv5-d16

STM32 Rule

Do not assume all STM32 targets are compatible.

Separate builds when any of these change:

  • Cortex core,
  • FPU mode,
  • compiler/toolchain,
  • ABI,
  • feature macros.

Library Scope

The STM32 presets compile Foundation as a static library. They intentionally do not select a concrete STM32 device macro, CMSIS package, HAL, startup file, interrupt vector table, memory map, linker script, or programmer. Those belong to the consuming firmware and may further narrow compatibility.

Build and Export

Example for STM32F407:

arm-none-eabi-g++ --version
./scripts/configure.sh stm32f407_armgcc_cortex_m4f_hard --fresh
./scripts/build.sh stm32f407_armgcc_cortex_m4f_hard \
--config Debug --target Foundation
./scripts/build.sh stm32f407_armgcc_cortex_m4f_hard \
--config Release --target Foundation
./scripts/export.sh stm32f407_armgcc_cortex_m4f_hard --fresh

If the compiler cannot find stdint.h, provide a compatible Newlib/runtime and FOUNDATION_ARM_SYSROOT. A compiler executable without target headers is not a complete cross-compilation installation.

Validation

Use arm-none-eabi-objdump -f to inspect the exported Release archive and verify the effective flags in build/<preset>/compile_commands.json. Then link the package into the real firmware using the same CPU/FPU/ABI flags. Hardware or emulator execution is the behavioral test; host CTest cannot execute Cortex-M objects. See Validation for the full checklist.
