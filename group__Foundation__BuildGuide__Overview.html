Foundation supports three main usage modes:

Source Mode

Source mode uses the repository directly.

This is the default mode for:

  • Arduino,
  • development,
  • debugging,
  • changing feature macros,
  • modifying Foundation internals.

In source mode, Foundation remains fully configurable through compile-time macros.

Desktop Development

For a Windows, Linux, or macOS application, use CMake FetchContent to make Foundation part of the application's build. This is the supported day-to-day development path: Foundation and CPSTL compile with the application's selected compiler, architecture, configuration, and C++ runtime. There is no separate Foundation export, installation, or CMAKE_PREFIX_PATH to configure.

Add this to the application's top-level CMakeLists.txt before linking the application target:

include(FetchContent)
FetchContent_Declare(Foundation
GIT_REPOSITORY https://github.com/ChecheRomo96/Foundation.git
GIT_TAG v0.0.1
)
FetchContent_MakeAvailable(Foundation)
target_link_libraries(MyApplication PRIVATE Foundation::Foundation)

The first configure downloads the pinned Foundation revision and its CPSTL dependency into the application's build tree; later builds reuse CMake's download cache. Configure the application normally for the platform you are developing on. The platform pages document the corresponding compiler and architecture choices.

Full Precompiled Mode

Full precompiled mode builds Foundation with all supported modules enabled.

This mode is intended for:

  • controlled Release distribution,
  • users that need a ready-to-link binary for one exact target,
  • generic full builds for known toolchains.

A full build is larger, but easier to consume. The official export contains the Release library only and remains specific to its preset's compiler and architecture. Debug is built from source when needed.

Custom Precompiled Mode

Custom precompiled mode builds Foundation for a specific target, toolchain, architecture, ABI, and feature set.

This mode is intended for:

  • embedded targets,
  • memory-constrained systems,
  • production builds,
  • projects that only need a subset of Foundation.

The selected modules are compiled into the package and recorded in FoundationBuildInfo.cmake. A different feature selection is a different compatibility product even when the target preset itself is unchanged.

General Rule

If macros change the compiled implementation, build a custom library. For normal desktop development, use source mode through FetchContent. If the project needs maximum flexibility, use source mode. Use a precompiled full build only when distributing a controlled Release binary for its exact target identity. Always validate a precompiled package with a separate consumer using the same target toolchain and ABI.
