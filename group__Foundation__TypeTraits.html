Detailed Description

Compile-time type inspection and relationships for generic code.

TypeTraits provides small, allocation-free compile-time utilities with an API shaped like the corresponding C++ standard-library traits. A trait exposes a compile-time value; C++17 consumers may use its shorter _v form.

#include <Foundation_TypeTraits.h>
using namespace Foundation::TypeTraits;
static_assert(is_integral<int>::value, "int must be integral");
static_assert(is_pointer_v<const char*>, "expected a pointer");
static_assert(is_same_v<remove_cv<const int>::type, int>,
"remove_cv must remove top-level qualifiers");

Every predicate has a C++17 _v convenience variable. The supported integral set is the standard C++17 set through char16_t, char32_t, and unsigned long long; compiler-specific extended integers are outside the v1 contract. is_unsigned_integer is a Foundation-specific composite trait that combines is_integral and is_unsigned while excluding bool; it is intended for numeric counters and storage representations.

Every available _v name is a C++17 inline variable equivalent to reading the corresponding trait's static Boolean constant. The class form remains useful when a trait type must be inherited from or passed to another metaprogram.

Current Contract

  • The project language baseline is C++17, so the documented _v forms are available on supported builds.
  • Traits are evaluated at compile time and do not allocate memory.
  • Foundation automatically uses the C++ standard <type_traits> backend when the header and the required C++17 invocation traits are available.
  • Toolchains without that standard-library support use Foundation's local fallback implementation. The public Foundation trait types and names stay identical regardless of the selected backend.
  • remove_const, remove_volatile, and remove_cv remove top-level qualifiers and expose the result as a nested type.
  • Function classification includes variadic, cv-qualified, ref-qualified, and noexcept function types.
  • Invocation checks support functions, function objects, member functions, and member objects through direct objects, pointers, dereferenceable wrappers, and reference-wrapper-like get() access.
  • is_nothrow_convertible is intentionally available under the C++17 baseline even though the similarly named standard trait was added later.
  • The API uses standard-style lowercase names intentionally; this is the documented naming exception to Foundation's normal PascalCase type style.
  • Include a public Foundation header instead of depending on transitive includes or implementation files.

Backend selection is an implementation detail and requires no consumer configuration. The conformance suite compiles every supported trait twice on desktop hosts: once through <type_traits> and once through the forced local fallback. Both routes are checked against the standard C++17 results.
