PSoC 5LP Cortex-M3 soft-float builds.

Collaboration diagram for PSoC:

PSoC 5LP Cortex-M3 soft-float builds.

Experimental Target Profile

Foundation provides this experimental target alias:

PSoC 5LP
ARM GCC
Cortex-M3
Soft Float

Target preset:

psoc5lp_armgcc_cortex_m3_soft

It inherits arm_none_eabi_cortex_m3_soft; today the alias changes package identity, not compiler flags. It therefore proves that Foundation can produce a Cortex-M3/Thumb/soft-float archive, but does not by itself prove PSoC Creator compatibility or execution on a PSoC device.

Why not every chip

Foundation should not initially generate one distribution per PSoC chip.

The minimum useful split is:

  • toolchain,
  • CPU core,
  • ABI/FPU mode,
  • configuration.

Since Foundation is mostly portable C++ and does not depend on chip registers, a compatible Cortex-M3 soft-float build may eventually cover a CY8CKIT-059 consumer. The preset currently produces a generic Cortex-M3 soft-float static archive. It does not provide PSoC Creator startup code, generated components, linker script, device headers, or project metadata.

The consuming PSoC project must use a compatible Arm GNU compiler/runtime and the same Thumb, Cortex-M3, and soft-float ABI. Compiler compatibility must be validated with the exact PSoC Creator/toolchain version used by the product. This is especially important for the Foundation C++17 contract: PSoC Creator 4.3 bundles GCC 5.4-2016-q2, whose C++17 mode was experimental and whose C++17 ABI was not yet stable. PSoC Creator also exposes an ARM GCC Generic integration for a separately installed compiler, but Foundation has not yet validated that path.

1.x Status Decision

PSoC 5LP remains EXPERIMENTAL in Foundation 1.x. VAL-009 records this as a deliberate status decision rather than unfinished generic compilation. Promotion requires all of the following evidence from the same environment:

  • an exact PSoC 5LP part or board and PSoC Creator version;
  • a C++17-capable selected ARM GCC toolchain and recorded version;
  • a clean Foundation package built with matching CPU, ABI, runtime, and compiler compatibility;
  • a real PSoC Creator consumer that links Foundation::Foundation or the installed archive without source-tree leakage; and
  • successful programming and execution of representative checks on hardware.

Official references:

  • Infineon CY8CKIT-059 product page;
  • PSoC Creator 4.3 release notes; and
  • GCC C++17 implementation status.

Export

Example:

./scripts/export.ps1 psoc5lp_armgcc_cortex_m3_soft

or:

./scripts/export.sh psoc5lp_armgcc_cortex_m3_soft

Output:

dist/psoc5lp_armgcc_cortex_m3_soft/

Inspect the Release archive with arm-none-eabi-objdump -f. Treat the output as experimental until it is linked into a PSoC Creator firmware using the exact product toolchain and executed on hardware. Do not use host CTest or generic cross-compilation as proof of PSoC compatibility.
