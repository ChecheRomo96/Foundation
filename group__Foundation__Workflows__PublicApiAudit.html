Inventory, findings, and freeze decisions for the Foundation 1.x API.

This page is the version-controlled evidence for backlog item V1-004. The audit distinguishes the API that consumers are meant to use from files that merely have to be installed because template definitions include them. Finding an issue here does not silently approve a breaking change. Every blocker and breaking decision must be resolved before the API is frozen.

Method and Scope

The audit reviewed:

  • the versioned headers staged by CMake under include/Foundation-<version>;
  • top-level and module umbrella headers;
  • public classes, aliases, free functions, constants, and macros;
  • namespaces and naming conventions;
  • const behavior and compile-time language requirements;
  • owned and non-owned storage, object identity, and lifetime assumptions;
  • direct module dependencies and feature-option behavior;
  • the compiled symbols in the Debug and Release static archives;
  • direct C++17 syntax compilation of every installed .h file;
  • selected behavioral comparisons for the TypeTraits API.

The default package currently stages 57 .h files and three .tpp files. All 57 headers pass a direct C++17 syntax check. The .tpp files are template implementation dependencies and are not promised as direct include entry points. Each rejects direct inclusion and names its supported declaring .h header.

Passing a syntax check proves only that a header can be parsed. It does not prove that the umbrella includes the intended symbols, that a partial package contains all dependencies, or that runtime behavior is safe.

The non-template compiled ABI is intentionally small. It currently contains Math::GCD and the out-of-line Frequency and Period members. Most of the consumer contract is header-defined and therefore requires extra care: even apparently small header changes can be source or behavior breaking.

Findings

ID Severity Area Finding and required disposition
API-001 BLOCKER Functional umbrella Resolved. Foundation/Functional.h now has its own guard, defines FOUNDATION_FUNCTIONAL, and includes the Functional module umbrella. Regression coverage consumes Foundation/Functional.h directly, consumes Foundation.h, and includes Functional with Utils in both possible orders.
API-002 BLOCKER Top-level headers Resolved. Foundation_Functional.h now exists, is staged and installed whenever Functional is enabled, and exposes the module through Foundation/Functional.h. Foundation.h consumes this top-level header consistently with the other modules, and a regression test compiles and uses it directly.
API-003 BLOCKER Feature macros Resolved. Module and component umbrellas use the same FOUNDATION_<MODULE> vocabulary as CMake, including FOUNDATION_MATH_* and FOUNDATION_FUNCTIONAL_CALLBACK; Containers and Scheduling have complete wrapper layers. Matrix and Time now each expose one truthful feature macro instead of misleading child options.
API-004 BLOCKER Module dependencies Resolved. CMake validates dependencies before creating targets and rejects invalid combinations with the exact conflicting options and corrective flags. Containers requires Utils; Time requires TypeTraits, Math, Math::Ratio, Functional, and Functional::Callback; Scheduling requires Time transitively. Valid reduced builds and representative invalid configurations are covered by configuration checks.
API-005 BLOCKER Matrix options Resolved. Matrix is an indivisible v1 feature controlled only by FOUNDATION_MATH_MATRIX. Its public API is grouped under Foundation::Math::Matrix as Fixed, Dynamic, and Multiply; choosing fixed or dynamic storage is a source-level decision.
API-006 BLOCKER Matrix overloads Resolved. The unused ColsB template parameter was removed from fixed-by-dynamic Matrix::Multiply. Regression coverage now invokes all four fixed/dynamic operand combinations using normal template deduction.
API-007 BLOCKER TypeTraits Resolved. The supported v1 subset is listed in Type Traits. Its stable Foundation API uses <type_traits> when the required C++17 facilities are available and otherwise selects the local fallback internally. Both backends run the same conformance comparisons covering extended character types, qualified and noexcept functions, private inheritance, conversions, member-function/member-object invocation, result shape, and invalid inputs such as is_unsigned<void>.
API-008 BREAKING DECISION Callback Resolved. The canonical forms are Callback<R, Args...>, Callback<R>, Callback<void, Args...>, and Callback<void>; an empty pack, never a void argument, represents no arguments. The API consistently uses Bind, Unbind, IsBound, and Invoke, supports non-const and const member functions, rejects null member instances as empty bindings, and documents bound objects as non-owned.
API-009 BREAKING DECISION Matrix::Dynamic Resolved. The type supports owned heap storage and attached caller-owned storage. Allocation failure is reported without exceptions, invalid and overflowing dimensions preserve existing state, copies own their data, moves transfer either storage mode with noexcept, and transpose/multiply reject overlapping output storage before mutation. AVR retains heap support while attached storage provides a deterministic alternative.
API-010 HARDENING Non-owning storage Resolved. CircularBuffer, Stack, and TaskScheduler expose storage validity and safely reject null pointers paired with non-zero capacities; null with zero capacity is a valid empty configuration. Callback already rejects null member instances. PeriodicTask and OneShotTask explicitly allow and forward null contexts, while null callbacks remain safe. Non-null storage, bound objects, task/context objects, and Clock identities remain non-owned and require caller-controlled lifetimes that cannot be inferred at runtime.
API-011 BREAKING DECISION Time model Resolved. Tick<T> defaults to uint32_t, requires a non-bool unsigned integer, and exposes the explicit Tick8, Tick16, Tick32, and Tick64 aliases. Time and Scheduling propagate a default Tick32 through their generic Basic...<TickType> families; the short public names use the template defaults. Duration rejects underflow and values outside the modular half-range; TimePoint subtraction and ordering handle counter rollover inside that range and produce an invalid Duration for incompatible or reverse subtraction. Clock object identity is retained through a non-owning pointer: Clock is non-copyable and non-movable, raw points can only be introduced by Now() or At(), and the Clock must outlive its points, tasks, and scheduler. BasicRatio<T> now provides distinct signed Ratio and unsigned UnsignedRatio specializations; Frequency and Period use the latter and require both terms to be non-zero, so every valid value has a valid reciprocal.
API-012 HARDENING Const/exception guarantees Resolved. Task::ShouldRun is a const readiness query and task mutation occurs in Run. Ratio and Time construction, access, mutation, validation, scalar conversion, and arithmetic are constexpr and noexcept where applicable; reciprocal time conversions are non-throwing. GCD and the rvalue cast performed by Utils::Move are also constexpr and noexcept, and Matrix::Dynamic moves remain non-throwing. Callback invocation paths, Clock::Now, scheduler execution, generic container element operations, and Utils::Swap deliberately do not promise noexcept because they may execute caller- or element-provided code. Compile-time assertions protect the supported guarantees.
API-013 HARDENING Naming Resolved. Public functions use PascalCase, Boolean queries use Is... or Has..., and descriptive noun accessors are preferred. Ratio, Frequency, and Period expose Numerator() and Denominator(); Matrix exposes RowCount() and ColumnCount(). Domain nouns such as Ticks(), Value(), Size(), and Data() remain concise and unambiguous. Get... remains valid for associated/configured objects where the noun collides with a public type, including GetFrequency(), GetPeriod(), and GetClock(). TypeTraits intentionally retains standard-compatible snake_case. These names are frozen for v1.0.
API-014 HARDENING Macro namespace Resolved. The unused global PROGMEM_MACRO, its unconditional AVR SDK include, and empty Arduino, ESP32, PSoC, and desktop preprocessor blocks were removed. The public build contract now contains only FOUNDATION_VERSION, FOUNDATION_CPLUSPLUS, and FOUNDATION_-prefixed feature/configuration macros. Platform detection is left to the compiler, toolchain, or consumer until Foundation provides a concrete portable abstraction that needs a platform contract.
API-015 HARDENING File surface Resolved. The empty Exchange.h and Forward.h placeholders were removed. CMake now records installed .tpp files separately from public headers: they remain package dependencies because their declaring template headers include them, but consumers must not include them directly. Supported consumer entry points end in .h and are either top-level/module umbrellas or documented component headers. Direct .tpp inclusion is rejected with guidance to the corresponding .h.
API-016 HARDENING Documentation/tests Resolved. Every module has regression consumers for its nested umbrella, top-level header, and Foundation.h entry point. TypeTraits, Containers, Functional, Scheduling, Time, Utils, Ratio, and Matrix::Dynamic have module and member-level reference documentation, including ownership, failure, invalid-state, and non-owning lifetime contracts.

TypeTraits Evidence

The original comparison consumer exposed five contract differences. The conformance suite now produces the expected result for each case:

is_integral<char16_t>: true
is_function<void() noexcept>: true
is_invocable<member, object>: true
is_nothrow_convertible<int, long>: true
is_unsigned<void>: false

The same tests compile once with automatic standard-backend selection and once with the local fallback forced. Both compare the Foundation result against <type_traits> where the corresponding trait exists in C++17. Foundation's is_nothrow_convertible is additionally tested against explicit throwing, non-throwing, invalid, and void conversion expectations.

Recommended Freeze Decisions

The recommended default decisions are:

  1. Retain the Foundation::<Module> namespace hierarchy.
  2. Retain PascalCase for Foundation object methods and standard-style snake_case only for TypeTraits.
  3. Add the missing Functional top-level header and make every umbrella include exactly its own module.
  4. Treat source mode as a full source distribution by default. Selective component headers may reduce includes; feature macros must describe real availability rather than pretending to remove files that are present.
  5. Make CMake reject invalid dependency combinations. Do not silently advertise a reduced package that cannot compile a consumer.
  6. Keep .tpp files installed where required, but classify them as implementation details rather than direct include entry points.
  7. Define every raw pointer as owned or non-owned in the declaration's documentation and state the required lifetime.
  8. Make the TypeTraits subset match the corresponding standard semantics for supported C++17 types and expressions.
  9. Keep both owned and attached Matrix::Dynamic storage. Report allocation failure without exceptions, preserve state on failure, and reject overlapping transpose or multiplication outputs before mutation.

Freeze Exit Criteria

V1-004 can move to DONE only when:

  • every BLOCKER has a merged fix and regression evidence;
  • every BREAKING DECISION has an approved, documented disposition;
  • installed top-level and component headers match the documented surface;
  • module dependencies cannot produce a known-invalid package;
  • ownership, lifetime, invalid-state, allocation, and aliasing contracts are documented for affected types;
  • Debug and Release tests pass after the selected changes;
  • a separate consumer compiles the approved umbrella and selective-header include styles;
  • the final public symbol/header inventory is recorded here;
  • no unresolved public API breaking change remains for RC1.

Exit evidence recorded on 2026-09-25: the macos_arm64 preset passed the then-current 122 registered tests in both Debug and Release. After TEST-002, the same preset passed the expanded 145-test suite in both configurations. TEST-003 further expands the current suite to 161 passing tests in both configurations. The repository-owned tests/PackageConsumer fixture then configured exclusively from the fresh Release export, compiled separate umbrella/selective-header translation units, linked Foundation::Foundation, called the out-of-line Frequency and Period conversions, and passed its executable test. Platform-matrix validation remains tracked separately and does not reopen the API design. Member-level traceability and known test gaps are recorded in Public API Coverage.
