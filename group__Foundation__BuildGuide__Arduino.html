Source-first Arduino integration and architecture-specific exports.

Foundation is designed to remain Arduino-compatible without modifying the repository structure.

Arduino requires:

library.properties
src/
examples/

Other directories such as docs, cmake, tests, scripts, and build support files are ignored by the Arduino IDE.

Source Mode

Arduino should normally use Foundation in source mode.

Language Level

Stock Arduino cores compile sketches as C++11 (Arduino AVR Boards 1.8.x uses avr-gcc 7.3.0 with -std=gnu++11), and a library cannot change that flag. When ARDUINO is defined, Foundation therefore accepts C++11 instead of its usual C++17 minimum, so the IDE works without editing the core. Below C++14, mutators such as Ratio::SetNumerator() are ordinary inline functions rather than constexpr; below C++17, the _v TypeTraits variables are not declared (use ::value). A core that already compiles as C++17 gets the full API.

Includes

The Arduino builder discovers a library only through a header in its src/ root. Include <Foundation.h> (or a root module header such as <Foundation_Math.h>) in the sketch before any nested header:

#include <Foundation.h>
#include <Foundation/Math/Ratio.h>

A sketch that includes only <Foundation/Math/Ratio.h> fails with No such file or directory because Foundation is never added to the include path.

Validation

scripts/test-arduino.sh, or scripts/test-arduino.ps1 on Windows, compiles every sketch under examples/Foundation for arduino:avr:uno from the repository's source layout with the unmodified core flags, and fails on any warning in Foundation or its examples because the core's -fpermissive otherwise hides type errors. It is the Arduino source-mode gate; other boards and cores are not validated by it.

Macros

Foundation modules may be selected using macros before includes.

Example:

#define FOUNDATION_FULL_BUILD
#include <Foundation.h>

Precompiled Arduino Libraries

Precompiled Arduino libraries are possible, but they are not universal.

They must be separated by architecture and core, for example:

atmega328p_avrgcc_avr5
arduino_samd_cortex_m0plus
arduino_esp32_xtensa

Source mode is recommended for Arduino unless a very specific target is known.

The atmega328p_avrgcc_avr5 export is a CMake package and target archive. It does not automatically create Arduino's architecture-specific precompiled library directory layout or board metadata. To distribute it through Arduino, verify the exact board core/toolchain version and package the archive according to that core's library rules. Otherwise, keep using source mode so the Arduino build compiles Foundation with the sketch's selected board flags.

SAMD, ESP32, and other Arduino architectures require their own explicit profiles; the ATmega328P AVR archive is not compatible with them.
