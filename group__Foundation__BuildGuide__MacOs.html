Apple Silicon and Intel macOS builds.

Collaboration diagram for macOS:

Apple Silicon and Intel macOS builds.

Supported target presets:

macos_x64
macos_arm64

Both presets use Apple Clang and Ninja Multi-Config. macos_arm64 sets CMAKE_OSX_ARCHITECTURES=arm64; macos_x64 sets it to x86_64. The compiler version and deployment environment are still part of practical compatibility and should be recorded with release artifacts.

Each preset uses one multi-configuration build tree. Select Debug or Release at build/test time; both archives share the local artifact directory, but only Release is exported to the distribution directory.

Apple Silicon and Intel builds must be treated as different artifacts unless a universal binary strategy is explicitly implemented. The current workflow creates thin, architecture-specific archives rather than combining them with lipo.

Day-to-day incremental build:

./scripts/build.sh macos_arm64 --config Debug --target Foundation

The build script configures the preset automatically. A complete manual release-candidate sequence is documented in Manual Workflow.

Clean release export:

xcode-select -p
ninja --version
./scripts/configure.sh macos_arm64 --fresh
./scripts/build.sh macos_arm64 --config Debug --target Foundation
./scripts/build.sh macos_arm64 --config Release --target Foundation
./scripts/export.sh macos_arm64 --fresh

The export contains libFoundation.a; libFoundation_d.a remains a local development artifact and is not distributed. Examples are excluded by default. Add --examples-on when the package should also contain Release API example executables. The package then includes one FoundationExamples.command launcher that can be opened from Finder. It shows a menu, runs the selected console binary, reports its status, and asks whether to run another. Press Enter or answer y to return to the menu; answer n or q to exit. Window closure after exiting follows Terminal > Settings > Profiles > Shell > When the shell exits. Close if the shell exited cleanly closes successful examples while leaving a failed example visible for diagnosis. Verify the package with:

lipo -info dist/macos_arm64/lib/libFoundation.a
test ! -e dist/macos_arm64/lib/libFoundation_d.a

Repeat with macos_x64; both commands must then report x86_64. An Intel consumer may require Rosetta to execute on Apple Silicon, but archive creation and architecture inspection do not.

Native CTest execution is part of the release check. The default feature set discovers and runs the module-owned GoogleTest cases in both Debug and Release. See Test and use the acceptance sequence in Validation.
