AVR-GCC builds for explicitly named 8-bit AVR devices.

Initial Supported Target

The initial AVR export profile is:

atmega328p_avrgcc_avr5

It selects the AVR-GCC C/C++ toolchain, the ATmega328P MCU, and the AVR5 architecture. Debug and Release share one build tree; the exported package is Release-only:

./scripts/export.sh atmega328p_avrgcc_avr5

The preset is an exact binary identity, not a generic “AVR” archive. The toolchain passes -mmcu=atmega328p to C/C++ compilation and executable link operations and records avr5 in package metadata.

dist/atmega328p_avrgcc_avr5/

Toolchain Configuration

cmake/toolchains/avr-gcc.cmake finds avr-gcc, avr-g++, avr-ar, and avr-ranlib. Set FOUNDATION_AVR_TOOLCHAIN_ROOT when the toolchain's bin directory is not on PATH.

A new AVR preset must use a device profile that fixes both FOUNDATION_AVR_MCU and FOUNDATION_AVR_ARCHITECTURE. Do not reuse the ATmega328P archive for another MCU merely because both are AVR devices.

Warning
AVR C++ standard-library support varies by toolchain distribution. Foundation avoids requiring the C++ standard library, but every new profile must still be compiled and consumer-tested with its intended AVR-GCC version. The toolchain disables exceptions and RTTI and enables -fcheck-new so a target allocator can report exhaustion with a null pointer.

Dynamic Memory

AVR builds may use heap-backed APIs; disabling exceptions does not disable the heap. Matrix::Dynamic::Allocate() reports failure with false rather than throwing. Arduino AVR Core provides the required non-throwing allocation functions. A bare-metal runtime must supply its own compatible new[] and delete[] implementation. Applications that require deterministic memory can attach a caller-owned buffer instead:

float storage[9] = {};
Foundation::Math::Matrix::Dynamic<float> matrix;
const bool attached = matrix.Attach(3, 3, storage);

Complete Local Sequence

avr-gcc --version
avr-g++ --version
./scripts/configure.sh atmega328p_avrgcc_avr5 --fresh
./scripts/build.sh atmega328p_avrgcc_avr5 \
--config Debug --target Foundation
./scripts/build.sh atmega328p_avrgcc_avr5 \
--config Release --target Foundation
./scripts/export.sh atmega328p_avrgcc_avr5 --fresh

The expected package archive is libFoundation.a. It must report elf32-avr and architecture avr:5; no Debug archive is distributed:

avr-objdump -f dist/atmega328p_avrgcc_avr5/lib/libFoundation.a
test ! -e dist/atmega328p_avrgcc_avr5/lib/libFoundation_d.a

Consumer Validation

Configure a separate AVR CMake project with the same ATmega328P toolchain, point CMAKE_PREFIX_PATH at the export, call find_package(Foundation CONFIG REQUIRED), and link Foundation::Foundation. The consumer must call a non-inline Foundation function so the linker actually reads the archive. Inspect the resulting ELF with avr-size, avr-nm, and avr-objdump before running it on hardware.

Repository CTest is not an AVR execution environment. Behavioral tests require an AVR emulator or board integration. See Validation.
